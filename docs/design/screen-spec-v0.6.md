# v0.6 화면설계서와 현재 앱 대조

앱: **모두의 육아 - 육아템 공동구매,핫딜**. 기준일: 2026-11-01. [사용자 원본 3084×10334](brand/source/screen-spec-v0.6.png)을 위에서 아래로, 각 줄의 왼쪽에서 오른쪽 순서로 읽어 50개 화면에 번호를 부여했다. 원본에는 번호가 없으므로 아래 번호를 후속 작업의 추적 ID로 사용한다.

이번 변경은 제공 브랜드 적용과 화면 대조다. **50개 화면 구현 완료를 뜻하지 않는다.** ‘연결’은 로컬 API와 해당 핵심 동선이 존재한다는 뜻이며 픽셀 일치·운영 출시 완료가 아니다. ‘부분’은 유사 기능이 있지만 중요한 상태·조건·동선이 다르다. ‘미구현’은 해당 전용 화면 또는 기능이 없다. 운영 데이터·결제·배송·실사용 효과 검증은 별도다.

## 개발 순서와 검증 기준

1. **상품·공구·주문 모델부터 정리한다.** Product/Variant → Campaign → 참여/Payment → Order/Shipment/Refund로 구분한다. 한 주문의 중복 결제/환불·과모집·권한 침범을 서버 시험으로 막는다. 운영 PostgreSQL 마이그레이션도 필요하다.
2. **v0.6 탐색 구조와 구매 전 동선을 연결한다.** 카테고리·검색·브랜드·타임세일·기획전과 기존 핫딜 진입을 실제 목록/상태에 연결한다. 빈 화면, 필터 복원, 뒤로가기, 로그인 후 복귀를 검증한다.
3. **커뮤니티를 별도 구현한다.** 글/댓글/사진·신고/차단/운영 이력을 구축하고 구매자·판매자·운영자 접근을 분리한다. 아동의 얼굴·실명·연락처가 공개되지 않도록 안내와 삭제/신고 흐름을 갖춘다.
4. **PG 샌드박스부터 거래 전 과정을 검증한다.** 결제 대기/실패/중복웹훅/마감경합/취소/미달/부분실패/복원까지 확인한 후 실거래로 넘어간다. 화면의 ‘자동환불’ 문구만 먼저 노출하지 않는다.
5. **추천·SEO/GEO는 현재 상품과 검증된 사실에 연결한다.** 공개 데이터 실험을 육아 상품 전환 성능으로 간주하지 않는다. 존재하는 공구·배송 포함 가격·마감만 답하고 검색 1위/인용을 보장하지 않는다.

각 화면의 완료는 실제 API·권한·예외 상태·모바일 화면·접근성·검증 증거까지 확인한 뒤 판정한다. [기존 101개 요구사항 대조](../build/requirements-status.md)와 함께 유지한다. 원본 화면설계서의 예시 수치·브랜드·후기·개인정보는 테스트나 실제 운영 데이터로 자동 채택하지 않는다.
