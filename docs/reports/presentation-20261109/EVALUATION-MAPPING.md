# 중간평가 기준과 모두의 육아 발표 대조표

사용자가 2026-11-09에 공유한 평가표와 운영 공지를 기준으로 작성했다. 배점 합계는 100점이다. 같은 산업 내 팀 간 평가이며, 주간 멘토링 일지가 심사위원에게 사전 공유된다.

## 최종 PPTX 평가항목별 발표 근거

본편은 1~15장, 부록은 16~36장이다. 35~36장에도 아래 대조표를 수록했다.

| 평가항목 | 배점 | 본편에서 제시한 근거 |
| --- | ---: | --- |
| 산업별 문제 정의의 적절성 | 10 | 2장 SCQA와 보호자의 비교·근거 확인 문제 가설 |
| 산업 구조 및 데이터 특성 이해도 | 10 | 3~4장 중개 역할, 사람·거래·세션의 분석 단위와 중복 |
| 문제 해결 아이디어의 창의성 | 15 | 3·7·8장 커뮤니티 질문과 비교·현재 정보·공식 근거의 연결 |
| 아이디어의 실무 적용 가능성 | 10 | 10~13장 배포 UI, 실기기 저장 왕복, DB와 검증 결과 |
| AI 기술 선정·적용 적절성 | 15 | 6·8장 모델 비교, 적용 시점의 제약, 소형 모델·검색·도구 역할 |
| AI 기술 구현 및 활용 수준 | 15 | 8~9장 RAG 흐름, 권한 기반 도구, Opik과 고정 평가 기록 |
| 데이터 활용 기획의 논리성 | 10 | 4~8장 발견에서 기능으로 연결, 외부 출처 범위와 갱신 |
| 데이터 활용의 진행 수준 | 5 | 5·7·11장 분석 수치, DB 반영, 실제 기기 연동 |
| 발표 내용 구성 및 전달성 | 10 | 1~15장 SCQA→분석→구현→검증, 계획 10분 대본 |
| 합계 | 100 | 장표별 근거와 수용 조건은 발표자 메모에 포함 |

## 발표자가 사용할 연결 문장

“저희는 육아 정보를 찾고 제품 조건을 비교하는 과정에서 출처와 사용자 경험이 흩어지는 문제를 다뤘습니다. 제공 자료를 분석하면서 소비자 선호가 서로 다르고, 거래 데이터에 중복이 있으며, 종료된 세션의 분류 성능을 현재 사용자의 구매 확률로 바로 해석하기 어렵다는 점을 확인했습니다. 그래서 사용자가 비교 기준을 직접 고르고, 커뮤니티 질문에 근거를 확인하며, 현재 서비스 정보를 함께 조회하는 구조를 구현했습니다.”

이 문장의 문제 정의는 프로젝트 가설과 멘토 피드백으로 설명한다. 제공된 해외 소매 자료만으로 국내 육아 이용자의 불편이나 시장 규모가 입증됐다고 말하지 않는다.

## 데이터 설명에서 지킬 정확성

- D1은 소비자1,000명이며 Baby Products 표본은41명이다. 국내 육아 소비자의 대표 표본으로 일반화하지 않는다.
- D2의541,909행은 D3와 중복되어 분석에 추가 합산하지 않았다. D3는1,067,371행의 과거 소매 자료다.
- D3의 조건부 Recall@5는 인기순0.1056, 연관 규칙0.3621이다. 과거 장바구니의 숨긴 품목 복원 실험이며 앱 구매 전환 성과가 아니다.
- D4는 종료 세션12,330개다. 연구용 분류 실험과 현재 운영의 CTA·관심 설정을 구분해 설명한다.
- 외부 데이터는 필수 요건이 아니다. 사용한 경우 출처·수집일·갱신·활용 위치를 제시한다. 공공자료 검토 스냅샷과 실시간 DB 조회를 구별한다.
- AI 검색 서비스가 우리 페이지를 실제 인용했다는 성과는 검증된 사례가 있을 때만 제시한다.
- 사용자 수·CTR 개선·전환율·모델 지연은 확인된 실행 기록만 사용한다.

## 시연과 협업

1. 로그인 없이 커뮤니티와 육아템 정보를 탐색한다.
2. 질문에 대한 근거·확인 시각·연결 화면을 보여준다.
3. 앱·웹에서 같은 계정의 저장 항목이 반영되는 모습을 보여준다.
4. 운영 품질 화면에서 고정 평가·오류·지연과 Opik 기록을 보여준다.
5. 멘토 피드백 원문, 반영된 요구사항, 실제 구현 증거를 연결한다.

발표 역할은 팀 합의 전 제안이다. 최용우는 문제·서비스 구조·시연, 이승현은 제공 데이터·AI 선택과 평가, 최유정은 UI·사용자 흐름·피드백 반영을 맡는 구성을 제안한다. 발표 시간은 공지 확인 후 본편 분량을 확정한다. 멘토링 일지에 없는 논의나 수행하지 않은 실험을 이력에 추가하지 않는다.
