# 제공 요구사항·화면 설계 자료 확인

Team_Wifi · 확인 기준 2026년 11월 3일

## 자료 위치와 확인 범위

사용자가 공유한 [Google Drive 폴더](https://drive.google.com/drive/folders/1RD9U3j9ycCwECVkDyUszQmQLu3L1gzTk)를 연결 도구로 읽었다. 제출 양식이나 평가표는 폴더 최상위 목록에서 확인되지 않았다. 이번 자료는 서비스 요구사항과 화면 설계의 근거다.

| 자료 | 확인한 구성 | 사용 목적 |
|---|---|---|
| [요구사항정의서.xlsx](https://docs.google.com/spreadsheets/d/1vdCgCTCK1tA-NmKWdn7xLzVSfQvy2KQj/edit) | 요구사항 128개, 번호 0~127, 요구사항 ID와 관련 화면 연결 | 목표 기능과 수용조건 확인 |

두 Excel 원본, 요구사항의 읽기용 텍스트, 화면설계서의 셀 텍스트, 전체 화면보드와 폴더별 목록을 E 작업 공간의 비공개 산출물에 보존했다. 홈 `001_PUB-01`, 추천 채팅 `100_CHAT-01`, 마이페이지 `131_BUY-01` 미리보기를 직접 확인했다. 346개 화면의 모든 클릭 경로와 배포 기능을 종단 시험한 것은 아니다. Drive 원본은 수정하지 않았다.

## 데이터 활용 보고서와 요구사항 연결

현재 구현 근거는 [데이터 활용 보고서](REPORT.md), [서비스 데이터 적용 기록](../../build/release-20261102/SERVICE-DATA.md), [인증·측정 기록](../../build/release-20261102/AUTH-AND-MEASUREMENT.md)이다. 아래는 데이터 활용 관련 주요 항목의 대조이며, 128개 전체 요구사항의 완료 판정표가 아니다.

| 요구사항 ID | 제공 자료의 목표 | 현재 확인한 적용과 남은 범위 |
|---|---|---|
| `signup_02`, `mypage_05` | 가입 뒤 관심 카테고리 온보딩, 개인설정에서 관심사 수정 | 현재 마이페이지에서 관심 분야 최대 3개와 비교 기준을 저장하고 홈에서 사용한다. 가입 직후 온보딩과 설계서의 메뉴 경로까지 완료된 것으로 확대하지 않는다. D1의 할인 민감도 차이는 선택권을 두는 설계 참고다. |
| `browse_06` | 상품 찜 상태의 계정별 일치, 개별구매·공동구매 담기 분리 | 저장과 고유 계정 집계는 구현 근거가 있다. 새 시안의 하트 위치·상태와 구매 방식별 장바구니 전체 동작은 별도 적용·검증 범위다. |
| `recommend_01`~`recommend_06` | 추천 버튼, 선물·구매 고민 대화, 상황·예산·일정 질문, 조건 변경, 빈 전송 방지 | 현재 확인한 홈 개인화는 관심 분야·저장 이력을 쓰는 규칙 방식이다. D4 연구용 LightGBM이나 D3 과거 상품 규칙이 이 대화 기능을 구현한 증거가 되지 않는다. 대화에서 받은 조건을 실제 카탈로그와 연결하고 재고·가격·조건 일치를 검증하는 추가 구현이 필요하다. |
| `recommend_07`, `recommend_08` | 명시적으로 채팅을 끝낼 때 삭제, 그 외 화면 이동·로그아웃·재로그인에는 계정별 대화 유지 | 제공된 대화 상태 설계다. 계정별 메시지·조건 저장과 삭제, 다른 계정에 대한 비노출을 구현·검증한 근거는 이번 보고서에 없다. |
| `seo_01` | 로그인 없이 열리는 메인·상품 웹주소, 공개 내용 일치, 비공개 주문·배송지·대화 보호 | 공개 탐색과 정적 비교 가이드, 검색용 메타데이터는 기존 구현 범위다. 새 상품 상세 전체와 검색 노출 성과까지 검증된 것으로 설명하지 않는다. |
| 운영 분석 관련 확장 | 데이터 근거와 실제 사용자 반응을 설명 | 제공 데이터 분석 근거, 함께 저장한 품목의 고유 계정 집계, 동의 기반 노출·CTA·저장·관심 측정은 현재 서비스 확장이다. 설계서의 일반 운영 현황과 동일한 기능이라고 간주하지 않는다. |

데이터를 연결하는 설명은 **자료 분석 → 설계 근거 또는 집계 방법 → 현재 기능 → 실제 효과를 확인할 측정** 순서로 유지한다. 대화형 추천이 추가되더라도 해외 소매 상품과 현재 육아 상품 사이에 없는 연결 키를 만들어 학습된 육아 추천이라고 주장하지 않는다.

## 구현 상태와 구분해야 할 사항

- `individual_01`, `groupbuy_02`, `payment_01`, 배송·환불·마일리지·판매자 정산은 목표 서비스 범위다. 현재 공개 서비스의 수요·관심 활동을 실제 주문, 결제, 환불이나 정산 완료로 설명하면 안 된다.
- `signup_01`, `login_01`의 목표는 이메일·카카오·네이버·구글이다. 최신 운영 기록은 기존 계정의 카카오 연결과 재로그인을 확인했고, Google 활성화는 프로젝트 한도 문제로 미완료다. 네이버 운영 인증 완료 증거도 없다.
- `login_06`은 운영자의 모바일 앱 로그인을 차단하고 PC 웹으로 안내하는 조건이다. 기존 운영자 카카오 웹 재로그인 성공과 이 모바일 차단 요구사항 충족은 별개다.
- `mypage_01`은 스크롤 본문 아래·고정 탭바 위의 회사·고객센터·정책 푸터를 요구한다. 제공 문서는 실제 회사 정보와 정책 본문이 미제공이라고 명시한다. 예시 정보로 운영 연락처나 사업자 정보를 채우지 않는다.
- `mypage_04`에는 운영정책 확정 후 보관 범위를 적용한다는 문장과 개인정보를 7년간 보관한다는 메모가 함께 있다. 개인정보 전체에 대한 일괄 7년 보관을 확정된 정책으로 옮기지 않는다. 실제 수집 항목·목적·보관 근거·삭제 시점을 확정해 현재 정책과 대조해야 한다.
- `history_01`, `content_time_01`은 기간 조회와 서버 기준 발생·등록·수정·처리 시각을 구분한다. 화면 예시의 날짜와 숫자는 운영 로그나 데이터 분석 성과가 아니다.

## 보고서와 발표에서의 사용

이 자료는 전체 프로젝트 보고서의 **요구사항 분석·화면 설계·후속 구현 범위**에 인용한다. 데이터 활용 8장 발표는 현재 확인한 분석과 적용을 설명하는 범위를 유지한다. 새 설계 화면을 시연에 쓰는 경우에는 화면 설계임을 밝히고, 실제 서비스 시연과 구분한다.

발표에서 “최종 설계에는 대화형 추천과 주문·결제까지 포함돼 있습니다. 현재 확인한 데이터 활용 구현은 관심 설정, 규칙 기반 개인화, 공동 저장 분석과 활동 측정입니다. 설계된 전체 거래 기능과 대화형 추천은 별도의 구현·검증 범위입니다.”라고 설명할 수 있다.

전체 요구사항의 완료율은 계산하지 않았다. 화면 개수, 요구사항 개수, 시험 개수는 서로 다른 단위다.
