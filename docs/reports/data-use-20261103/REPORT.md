# 모두의 육아 제공 데이터 분석과 서비스 적용 보고서

Team_Wifi · 작성 기준 2026년 11월 3일

## 연구 목적과 결론

우리 팀은 육아용품을 비교하고 관심 품목을 저장하며 공동구매 수요를 나누는 서비스를 개발했다. 제공된 데이터는 국내 육아 서비스의 실거래 원장이 아니므로, 자료마다 분석 단위와 적용 가능한 범위를 먼저 확인했다. 소비자 행동 자료로 비교 기준의 차이를 탐색하고, 중복 거래를 제거하며, 소매 거래의 동시구매 분석과 쇼핑 세션의 구매 여부 분류를 실험했다. 이후 관심 설정과 설명 가능한 관심 목록, 운영자의 공동 저장 분석, 동의 기반 노출·클릭·저장 측정을 서비스에 구현했다.

현재 홈의 개인화는 이용자의 명시적 관심 분야와 저장 이력을 이용한 규칙 기반 방식이다. 제공 자료로 학습한 LightGBM이 현재 회원의 구매 확률을 계산하거나 홈 상품의 순서를 정하지 않는다. 동시구매 실험의 수치와 실제 앱의 성과도 구분한다. 기능 구현과 배포는 확인했으며, 국내 이용자의 구매 전환·매출 증가·CTR 개선 효과는 아직 확인하지 않았다.

이 보고서는 전체 프로젝트 최종 보고서 중 **데이터 분석과 활용 부분**에 해당한다. 제출 양식이 정해지면 문제 정의, 팀 역할, 전체 시스템 구성, 일정과 함께 편집할 수 있다.

2026년 11월 3일 추가 제공된 요구사항정의서 128개 항목과 화면 설계 자료를 확인했다. [요구사항·화면 설계 대조 기록](DESIGN-REFERENCE.md)에 관심 설정·추천·저장·공개 웹 요구사항을 현재 구현과 연결했다. 설계의 대화형 추천과 주문·결제 등 전체 목표 범위는 이 보고서의 구현 완료 범위와 다르다. [S9]

## 제공 데이터와 분석 단위

| 구분 | 자료 | 규모와 단위 | 이번 프로젝트의 사용 |
|---|---|---|---|
| D1 | Ecommerce Consumer Behavior Analysis Data | 1,000행 × 28열, 소비자 단위 | 할인 민감도와 구매 분류의 기술통계, 관심 설정 설계 근거 |
| D2 | Online Retail Transaction Data | 541,909행 × 9열, 거래 항목 단위 | D3와의 중복 감사. 추가 index를 제외한 8업무열 비교 |
| D3 | UCI Online Retail II | 1,067,371행, 2시트, 8업무열 | 거래 정제, 상품·RFM 집계, 월별 판매량 기준모델, 동시구매 실험 |
| D4 | UCI Online Shoppers Purchasing Intention | 12,330행 × 18열, 종료된 방문 세션 단위 | 구매 여부 분류 실험, 특징 누수·실시간 적용 가능성 검토 |

제공된 회사 DOCX와 보존 Notion 자료는 서비스 요구사항과 운영 맥락을 파악하는 데 사용했다. 통계 표본이나 구매·매출 자료로 합산하지 않았다. D1의 소비자, D3의 거래 고객, D4의 세션, 현재 서비스 계정 사이에는 검증된 연결 키가 없다. 따라서 임의로 결합하지 않았다.

D1의 실제 수집·표집 방식과 실측/합성 여부는 확인하지 못했다. D2의 재게시 라이선스 세부 조건도 불명확하여 보고서에는 집계와 출처만 제시한다. D3는 2009~2011년 영국 소매업체의 선물용품 중심 거래이며 도매 거래도 포함할 수 있다. D4는 현재 한국 육아용품 이용자의 행동 기록이 아니다. [S1, S2]

## 분석 방법과 발견

### D1 소비자마다 다른 할인 민감도

전체 1,000명 중 할인에 매우 민감한 소비자는 350명(35.0%), 어느 정도 민감한 소비자는 319명(31.9%), 민감하지 않은 소비자는 331명(33.1%)이었다. Baby Products로 분류된 표본은 41명이며 각 집단은 15명, 11명, 15명이었다. 전체 표본의 분포를 국내 육아 고객의 선호 비율로 일반화할 근거는 부족하다.

이 결과를 제품 설계의 참고 근거로 삼아 이용자가 관심 분야를 최대 3개 선택하고, 골고루 살펴보기·가격과 수량·구성과 규격·사용과 관리 중 비교 기준을 직접 고르게 했다. 해당 선택지가 통계적으로 최적이라는 결론을 내린 것은 아니다. 선택지가 유용한지는 실제 서비스 자료로 검증해야 한다.

`Purchase_Intent`는 Need-based, Wants-based, Impulsive, Planned라는 구매 성향 분류다. 구매 성공/실패 정답으로 취급하지 않았다. `Occupation`의 값도 Middle/High여서 직업별 타기팅에 사용하지 않았다. [S1, S3]

### D2와 D3 중복 거래 감사

D2의 추가 index를 제외한 송장번호·상품코드·설명·수량·일시·단가·고객번호·국가를 정규화했다. 같은 행의 반복 횟수를 유지하는 튜플 다중집합으로 비교한 결과, D2의 541,909행 전부가 D3의 두 번째 시트에 포함됐다. 해당 D3 시트에는 운송료 항목 1행이 더 있었다.

D2와 D3를 단순 연결하면 1,609,280행으로 보이지만 독립된 추가 거래가 아니다. 거래 분석은 D3를 기준으로 진행했다. 별도로 D3 내부의 업무열 중복은 34,335행이며, 수량·단가가 0 이하인 행, 취소 송장, 빈 설명, 상품코드 조건을 통과하지 못한 항목 등을 제외한 양수 판매 분석 대상은 1,003,213행이다. 이 수를 순매출이나 잠재 수요로 부르지 않는다.

이 감사와 별개로, 실제 서비스에서도 같은 회원의 반복 저장과 관심 표시를 중복 성과로 세지 않도록 고유 키와 고유 계정 집계를 적용했다. D2의 행을 앱 DB에 넣은 것이 아니라 중복 관리 원칙을 반영한 것이다. [S2, S3, S5]

### D3 동시구매 실험과 서비스 공동 저장 분석

영국 거래의 송장을 시간순으로 정렬하고 앞 80%인 28,947개를 학습, 뒤 7,237개를 평가에 사용했다. 학습 구간 상위 100개 품목의 동시 출현으로 지지도·신뢰도·향상도를 구했다. 두 품목을 함께 포함한 학습 송장이 100개 이상인 규칙을 보존했다.

평가에서는 학습 상위 품목을 2개 이상 포함한 4,338개 송장만 사용했다. 각 송장에서 품목 1개를 결정적으로 숨기고, 나머지 품목을 알고 있을 때 상위 5개 제안으로 숨긴 품목을 찾는지를 측정했다. 규칙 추천은 신뢰도로 정렬했다.

| 평가 지표 | 인기순 기준모델 | 동시구매 규칙 |
|---|---:|---:|
| 조건부 Recall@5 | 0.1056 | 0.3621 |
| MRR@5 | 0.0563 | 0.2276 |

Recall@5의 차이는 약 25.66%p다. 이는 **과거 거래에서 나머지 장바구니가 알려진 조건의 품목 복원 실험**이다. 다음 주문 예측, 새로운 고객 일반화, 한국 육아템 추천 성능 또는 앱 전환율 상승으로 해석할 수 없다. 같은 과거 고객이 학습과 평가에 다시 등장할 수 있다.

실제 서비스에는 동시 출현을 세는 원리를 적용했다. 운영자 분석 화면은 현재 육아템을 함께 저장한 서로 다른 계정 수를 집계한다. 5계정 이상이 함께 저장한 조합만 보여준다.

- 공동 저장 지지도 = A와 B를 함께 저장한 계정 수 ÷ 현재 목록의 품목을 하나 이상 저장한 계정 수
- A 저장자 중 B도 저장한 비율 = 공동 저장 계정 수 ÷ A 저장 계정 수
- B 저장자 중 A도 저장한 비율은 별도로 계산한다.

서비스는 이 비율과 계정 수를 보여주며, 연구 파이프라인의 전체 규칙·향상도 순위를 그대로 이식하지 않는다. 운영자는 해당 신호를 비교 가이드나 공구 조사 주제 선정에 참고할 수 있다. 저장을 구매 의사 확정이나 주문으로 보지 않는다. [S3, S4, S5]

### D3 추가 연구 범위

정제 거래에는 39,516개 송장과 4,877개 상품이 있다. 고객번호가 있는 5,852명의 RFM을 집계했고 최근 구매일·구매빈도·양수 판매금액의 분포만 보존했다. 고객별 원문 행을 서비스에 배포하지 않았다.

월별 양수 판매량은 과거 월만 사용하는 rolling-origin 방식으로 2011년 1~11월의 기준모델을 평가했다. 직전 월 값의 WAPE는 15.29%, 전년 동월 값은 9.80%였다. WAPE는 절대오차 합을 실제 판매량 합으로 나눈 값이다. 9.80%를 ‘예측 정확도 90.2%’로 바꾸지 않는다. 부분 월인 2011년 12월은 제외했다. 재고·품절·가격·노출 정보가 없어 현재 서비스 수요 예측에는 연결하지 않았다. [S3, S4]

### D4 종료 세션 구매 여부 분류

12,330개 세션 중 구매 세션은 1,908개(15.47%)였다. 상품 페이지 체류시간 중앙값은 구매 세션 1,109.91초, 미구매 세션 510.19초였다. 세션 종료 집계이므로 구매 이후 체류도 포함될 수 있고, 오래 머물게 하면 구매가 증가한다는 인과관계를 뜻하지 않는다.

PageValues·BounceRates·ExitRates 등을 입력에서 제외하고 방문 횟수·체류시간·SpecialDay·Weekend 등 8개 특징을 사용했다. 선택 특징값이 같은 행이 학습·검증·평가에 동시에 들어가지 않도록 그룹 분할했다. 목표 비율은 60/20/20이며 실제 표본 수는 7,219/2,365/2,746개다. 특징 그룹의 분할 간 겹침은 0이지만 사람이나 실제 시간에 따른 외부검증은 아니다.

| 모델 | 검증 AP | 평가 AUROC | 평가 AP |
|---|---:|---:|---:|
| 구매 비율 기준모델 | 0.1751 | 0.5000 | 0.1522 |
| 로지스틱 회귀 | 0.2758 | 0.7223 | 0.3054 |
| LightGBM | 0.2811 | 0.7448 | 0.2937 |

모델 선택은 검증 AP로 했으므로 LightGBM을 보존했다. 평가 AP는 로지스틱 회귀가 더 높다. 모든 지표에서 LightGBM이 우수하다고 주장하지 않는다. AP는 불균형 분류에서 정밀도·재현율을 요약하는 지표이며 구매 전환율이 아니다.

이 모델은 연구용으로 보존했다. 현재 서비스에서는 자동 구매 점수나 점수 기반 CTA를 사용하지 않는다. 이용자가 선택한 비교 기준에 따라 안내를 제공하고 단가 계산기로 연결한다. 실시간 모델을 도입하려면 ‘방문 시작 후 30초’처럼 예측 시점을 정한 자료, 그 시점까지의 특징, 이후 실제 결과와 별도 시간순 평가가 필요하다. [S1, S6]

## 실제로 반영한 화면과 동작

| 이용 위치 | 현재 구현 | 데이터 활용 성격 |
|---|---|---|
| 마이페이지 → 관심 육아템 설정 | 최대 3개 관심 분야와 비교 기준 저장·수정·초기화 | D1에서 확인한 차이를 설계에 반영 |
| 홈 → 내 관심 육아템 | 선택 분야 우선, 없으면 본인 저장 분야 사용. 만료 제외·미저장 우선·최대 3개와 이유 표시 | 실제 계정 정보에 대한 규칙 기반 개인화 |
| 홈 비교 안내와 단가 비교 | 배송비를 포함한 총액과 같은 단위의 가격 비교 | D1의 선택권, D4의 실시간 예측 한계를 반영 |
| 마이페이지 → 육아템 관심 분석 | 카테고리별 저장·수요·관심의 고유 계정 집계 | 실제 서비스 자료. 운영자만 접근 |
| 같은 화면 → 함께 저장한 육아템 | 공동 저장 5계정 이상 조합과 두 방향 비율 | D3의 동시 출현 집계 방법 활용 |
| 같은 화면 → 제공 데이터 분석과 적용 근거 | D1~D4 집계·적용·한계·원출처 표시 | 제공 데이터 분석의 추적 가능성 |
| 같은 화면 → 노출·클릭·저장·관심 | 동의한 일반 회원의 실제 행동과 계정 기준 CTR | 앞으로 효과를 검증할 측정 기반 |
| 공개 가이드 | 단가 비교·젖병 구성·데이터 근거의 정적 HTML | 분석과 비교 기준을 검색 가능한 설명으로 제공 |

앱과 웹은 같은 API/DB를 사용한다. 같은 계정의 관심 설정과 저장 자료를 다시 조회하면 공유된다. 화면 간 실시간 푸시 동기화를 구현했다는 뜻은 아니다. 최신 웹 반영과 Android 파일 생성은 완료했지만 Android 0.5.0(code 7)의 Play 업로드·실기기 확인은 미완료다. 따라서 기존 설치 앱에 새 프런트 화면이 이미 반영됐다고 설명하면 안 된다. [S5, S7, S8]

## 실제 효과를 측정하는 방법

노출은 화면의 50% 이상이 1초 연속 보였다고 클라이언트가 보고했을 때 기록한다. 이후 상세 보기·출처·계산기·저장·관심 CTA를 연결한다. 계정×항목×위치×플랫폼×한국 날짜로 중복을 관리하며, 최근 30일의 위치·플랫폼별 CTR은 고유 클릭 계정 수를 고유 노출 계정 수로 나눈다. 이벤트 클릭 수를 단순히 노출 횟수로 나누는 방식과 다르다.

서버가 확인한 신규 저장·관심 완료만 30분 이내 마지막 측정 클릭에 귀속한다. 반복 저장은 전환을 늘리지 않는다. 측정은 기본 미동의이며 운영자·비회원·비동의 회원은 통계에서 제외된다. 1~4명인 분자·분모와 관련 비율을 숨긴다. 95% Wilson 구간을 표시하고 최소 200개 노출 계정, 클릭·미클릭 각 20개 계정 전에는 효과 판단을 보류한다. 이 기준을 넘더라도 관찰 자료이며 A/B 실험의 유의성을 증명하지 않는다.

향후 검증은 비교 안내 사용률과 저장 완료율을 먼저 확인하고, 사전에 기간·표본·주지표를 정한 무작위 비교 실험으로 확장할 수 있다. 실제 구매 시스템과 구매 정답이 없으므로 저장을 구매 전환으로 명명하지 않는다. Search Console의 검색 CTR과 AI 답변 인용은 별도 측정 대상이다. [S7]

## 검증 범위와 재현성

이번 보고서 작성 시 보존 원본 네 파일의 SHA256을 기존 감사값과 다시 대조했고 D1·D4 집계를 다시 계산해 서비스의 집계 JSON과 일치함을 확인했다. D2/D3 중복·규칙 평가와 D4 모델 평가는 저장 산출물과 분석 코드를 대조했다. 이 보고서 작성 과정에서 전체 모델을 다시 학습하거나 전체 거래 실험을 재실행하지 않았다.

현재 기능 소스 `8fde8abbc266078db09c8dd240b86bca1ba491fa`의 CI는 서버 123개, 프런트 155개, PostgreSQL 67개 검사를 통과했다. 이 수는 인증 등 다른 기능도 포함한 전체 검사 수이며 ‘데이터 모델 정확도 검사 345개’라는 표현으로 바꾸지 않는다. 데이터 관련 검사에는 계정 간 분리, 설정 공유, 중복 저장, 소수 집계 숨김, 만료 제외, 노출 순서와 전환 귀속을 포함한다. 정식 웹과 API에 동일 소스를 배포했다. [S8]

발표 화면의 5명·100% 공동 저장 사례는 격리된 합성 계정으로 기능을 확인한 화면이다. 운영 고객의 성과로 사용하지 않는다. 데이터와 구현을 검증한 것과 서비스 효과를 입증한 것을 구분한다.
