## 이번 주 목표와 결과

육아템 선택에 필요한 정보와 커뮤니티 수요를 연결하는 서비스를 구체화하고, 제공 데이터의 품질과 활용 가능성을 분석했다. 분석 결과를 관심 설정, 조건별 탐색, 공동 저장 집계, 비교 안내에 반영하고 공개 웹과 API에 배포했다. 현재 공개 범위는 정보 탐색·비교·저장·수요 커뮤니티이며, 실제 결제·배송·정산은 후속 범위다.

이번 주에는 데이터 분석을 서비스 기능으로 연결하는 기반을 마련했다. 11월 4일 멘토 피드백을 반영해 다음 핵심 개발 대상으로 출처 기반 챗봇, 질문 시점의 DB/API 조회, Opik을 이용한 답변 평가를 설계했다. 자유대화 RAG와 Opik 운영 연결은 아직 구현 전이다.

## 데이터 분석과 서비스 반영

데이터의 분석 단위와 중복을 먼저 확인했다. 과거 해외 거래, 종료된 방문 세션, 현재 서비스 계정 사이에는 검증된 연결 키가 없으므로 임의로 결합하지 않았다.

| 제공 자료 | 확인한 내용 | 서비스 적용과 해석 범위 |
|---|---|---|
| D1 소비자 1,000명 | 할인 민감도 350명·319명·331명. 육아용품 표본 41명 | 관심 분야 최대 3개와 비교 기준을 직접 선택하게 함. 국내 육아 고객의 대표 통계로 일반화하지 않음 |
| D2 거래 541,909행 | 업무열 기준 D3 두 번째 시트에 전부 포함 | 거래량 중복 합산 제외. 서비스의 반복 저장·관심도 고유 계정 기준으로 집계 |
| D3 소매 거래<br/>1,067,371행 | 거래 정제와 동시 출현 규칙 평가 | 집계 방법을 실제 공동 저장 분석에 적용. 과거 해외 SKU를 육아 상품으로 임의 치환하지 않음 |
| D4 종료 세션 12,330개 | 구매 세션 1,908개. 분류 모델과 기준모델 비교 | 연구용 모델로 보존. 실시간 구매 확률 대신 선택한 비교 기준에 맞춘 CTA 제공 |

### 동시구매 규칙 평가

시간순으로 나눈 과거 거래에서 장바구니 품목 하나를 숨기고 나머지 품목으로 복원하는 실험을 수행했다. 평가 대상 4,338개 송장의 조건부 Recall@5는 인기순 0.1056, 규칙 추천 0.3621이었다. 이 결과는 우리 앱의 구매율이나 현재 육아템 추천 정확도가 아니다.

서비스에서는 서로 다른 활성 일반회원 5계정 이상이 함께 저장한 조합을 관련 목록의 근거로 사용한다. 데이터가 부족하면 같은 분야의 공식 목록 또는 빈 상태를 보여준다. 저장은 주문이나 구매 확정으로 세지 않는다.

### 종료 세션 모델 평가

| 모델 | 평가 AUROC | 평가 AP |
|---|---|---|
| 로지스틱 회귀 | 0.7223 | 0.3054 |
| LightGBM | 0.7448 | 0.2937 |

LightGBM은 검증 AP로 선택했지만 평가 AP는 로지스틱 회귀가 더 높았다. 종료 세션의 방문·체류 집계를 현재 진행 중인 세션에 그대로 넣을 수 없으므로, 실시간 이탈 예측·동적 구매 점수는 운영에 적용하지 않았다.

분석 결과는 비교 선택권, 중복 방지, 관련 목록의 근거 표시와 실제 반응 측정으로 연결했다. CTR·저장율·매출 향상은 아직 입증하지 않았다.

## 시스템과 DB 구성

웹은 React 19·Vite·TypeScript, Android는 Capacitor를 사용한다. 두 클라이언트가 같은 FastAPI 서버를 호출하며, 서버는 SQLAlchemy를 통해 Neon PostgreSQL에 접근한다. DB 접속정보는 서버에서 관리한다.

| 계층 | 역할 |
|---|---|
| 웹과 Android | 탐색·비교·저장·커뮤니티 화면. 로그인 세션은 각각 유지 |
| FastAPI | 인증·권한·요청 제한, 공개 목록 및 회원별 자료 조회·수정 |
| Neon PostgreSQL | 회원·인증·저장·관심 설정·수요 글·댓글·동의·측정 기록 |
| 공개 파일 | 공식몰 참고 카탈로그, 검토한 분석 집계, 정적 비교 가이드 |

### 현재 DB 테이블

| 테이블 | 주요 역할 |
|---|---|
| users | 회원 ID, 이메일, 비밀번호 해시, 닉네임, 권한·탈퇴 상태 |
| tokens | 회원과 연결된 인증·복구 토큰의 해시 및 만료 |
| rate_buckets | 요청 제한을 위한 가명 키와 횟수·만료 |
| records | 종류와 소유 계정으로 구분한 서비스 활동·설정·소셜 연결 |

조건 찾기는 records의 release_advisor 종류에 계정별로 저장한다. 같은 계정으로 다시 조회하면 앱과 웹에서 같은 저장 자료를 읽는다. 계정 간 접근은 제한하며, 비회원 조건 미리보기는 계정 자료로 보관하지 않는다. 실시간 푸시나 오프라인 병합이 구현됐다는 뜻은 아니다.

## 멘토 피드백과 반영

커뮤니티 서비스의 핵심 기능으로 챗봇을 강화하고, RAG 설계에서 실시간 데이터를 조회하며 Opik으로 분석하라는 피드백을 받았다. 이에 승인한 비교 자료·서비스 안내를 검색하고, 현재 공개 글·본인 저장 기록은 질문 시점에 권한을 확인해 읽는 구조를 설계했다.

Opik에서는 검색 근거, 도구 호출, 답변의 근거 충족, 단계별 지연·오류를 비교한다. 다음 주에는 고정 평가 30문항을 구성하고 검색 Recall@5와 인용·권한 검사를 진행할 계획이다. 현재는 평가 목표를 정한 단계이며 RAG 성능이나 Opik 실험 결과는 없다.

기존 조건 찾기·공동 저장 추천·공개 가이드를 챗봇의 도구와 근거로 재사용한다. 생성 모델과 Opik 실행 환경은 무료 사용 조건·개인정보 처리·응답 지연을 확인한 뒤 연결한다. 다음 수행일지도 작업 내용, 증거, 문제점, 후속 계획을 같은 기준으로 누적한다.
