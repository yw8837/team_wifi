# 주차별 수행일지 제출 기록

마감 기준은 각 교육 과제 화면의 한국 시간이다. 2026-11-04 사용자가 제공한 화면에서 1주차 마감과 미제출 상태, 2~4주차 제출 메뉴를 확인했다. 기존 공유 일정의 ‘매주 일요일 23:59’는 이 과제의 마감 근거로 쓰지 않고 정정했다.

| 주차 | 확인한 마감 | 자료 준비 | 접수 확인 |
|---|---|---|---|
| 1주차 | 2026-11-04 23:59 KST | 수행일지 PDF 5쪽·편집 원문 작성 및 페이지 검수 완료. 지정 양식 대조 필요 | 사용자 제공 화면상 미제출. 업로드·접수 증거 없음 |
| 2주차 | 과제 화면 확인 필요 | 1주차 이후 실제 작업을 누적 | 미확인 |
| 3주차 | 과제 화면 확인 필요 | 해당 주 실제 작업을 누적 | 미확인 |
| 4주차 | 과제 화면 확인 필요 | 해당 주 실제 작업을 누적 | 미확인 |

파일명·접수 일시·제출 상태를 실제 결과로 확인한 뒤 접수 칸을 갱신한다. 파일 작성과 제출 완료를 구분한다. 주차별 날짜를 일괄 추정하거나 자동 제출·자동 완료 처리하지 않는다.

## 매주 유지할 항목

1. 주차, 팀명, 팀원, 작성 기준일.
2. 이번 주 목표와 실제 수행 내용.
3. 분석 결과와 서비스 적용, 관련 코드·자료·화면 증거.
4. 검증 결과와 확인하지 못한 범위.
5. 문제점, 멘토 피드백, 다음 주 작업과 담당.
6. 제출 파일, 제출처, 마감, 실제 접수 상태.

이번 1주차 원문은 `WEEK-01.md`이며 지정 양식과 업로드 조건은 과제 URL을 확인한 후 대조한다. 현재 웨일 창 연결 오류로 첨부 양식·과제 업로드 조건을 읽지 못했다. 메일과 접근 가능한 Drive·공유 시트에도 지정 양식은 확인되지 않았다.

## 준비 파일과 검수

- 제출용 PDF: `output/pdf/Team_Wifi_1주차_수행일지_20261104.pdf`.
- 편집 원문: 이 폴더의 `WEEK-01.md`. 재작성 기준: `WEEKLY-TEMPLATE.md`.
- 재생성: 번들 Python과 reportlab로 `build_weekly.py` 실행. 공개 화면 2장은 `assets/`에 보존했다.

- 본문 핵심 수치·팀원 이름·미구현 표기와 클릭 가능한 HTTPS 근거 링크 8개를 확인했다. 페이지 검수 이미지는 비공개 `artifacts/weekly-20261104/`에 두며 제출하지 않는다.
- 공유 시트 일정에 1주차 마감과 미제출 상태를 반영했고, 2~4주차는 기한 확인 필요로 유지했다.
