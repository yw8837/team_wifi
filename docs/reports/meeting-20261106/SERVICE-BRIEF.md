# 모두의 육아 — 회의용 서비스 브리프

2026년 11월 6일 · Team_Wifi · 이승현·최유정·최용우

**육아 정보와 경험을 나누고 질문을 해결하는 커뮤니티에 육아템 비교와 공동구매 수요 연결을 더한 서비스다.** 회원이 공구 정보를 공유하고 수요 글에 연결한다. 실제 주문·결제·배송·환불은 외부 판매처에서 진행하며, 플랫폼은 판매처로 이동하기 전에 거래 주체와 조건 재확인을 안내한다.

## 이용자가 할 수 있는 일

하단 메뉴는 **공구 찾기 · 공구 수요 · 단가 비교 · 저장 · 마이**, 챗봇은 별도 버튼이다. 로그인 없이 탐색·챗봇 이용이 가능하고, 글·댓글 작성과 저장·관심 등 본인 기록을 남기는 행동에는 로그인이 필요하다.

- **정보 탐색·비교:** 진행/종료 공구 구분, 검색·정렬, 출처와 확인 시각, 배송비 포함 단가 계산, 공식 비교 가이드.
- **커뮤니티:** 질문·경험·정보·수요 글, 댓글, 수요 관심 표시와 진행 공구 연결, 내 활동·기간 검색, 신고·작성자 차단.
- **운영:** 앱·웹에서 신고 대상과 원문 확인, 공구 숨김·확인 필요·조치 없이 종결을 구분하고 사유·시각을 기록. 숨긴 공구의 공개 본문·판매처 링크와 수요의 연결 공구 노출을 제거한다.

## 앱과 웹은 같은 계정 기록을 사용한다

웹과 Android 앱 → 같은 FastAPI API → **기존 Neon PostgreSQL**로 연결된다. 회원·소셜 연결과 `records` 구조를 유지하며, 같은 서비스 계정으로 로그인해 다시 조회하면 저장·관심·설정·글·선택 저장한 대화를 함께 볼 수 있다. 기기별 로그인 세션은 별개다. 이메일이 같다는 이유로 소셜 계정을 자동 병합하지 않으며 화면 간 실시간 푸시 동기화를 의미하지 않는다.

서버가 현재 계정과 대상 권한을 결정한다. 수정 충돌은 revision으로 알리고, 반복 저장·관심·신고는 계정과 대상의 조합으로 중복을 막는다. 대화 저장은 회원이 선택한 경우에만 적용하며 보존 기간은 마지막 성공한 저장 활동부터 30일이다.

## 제공 데이터와 현재 DB의 용도를 나눈다

| 제공 자료 | 확인·실험한 내용 | 서비스에 반영한 원리 |
|---|---|---|
| 소비자 행동 1,000행 | 할인 민감도·선택 기준의 차이 | 관심 분야와 비교 기준을 이용자가 직접 선택 |
| 소매 거래 541,909행 및 Online Retail II 1,067,371행 | 두 자료의 중복 감사, 정제 거래의 동시구매 분석 | 반복 행동 중복 방지, 실제 계정의 공동 저장 집계 |
| 쇼핑 종료 세션 12,330행 | 구매 여부 분류와 실시간 적용 한계 | 연구 모델은 보존하고 현재 화면은 선택 기준에 따른 안내 제공 |

이 자료와 현재 회원 사이에는 검증된 연결 키가 없다. 과거 거래 행을 현재 공구·재고·육아 지식으로 사용하지 않는다. 현재 개인화는 본인 관심·저장에 따른 규칙 기반이며, 연구용 LightGBM이 회원의 구매 확률을 계산하지 않는다. 실제 DB에서는 공개 공구·커뮤니티와 본인 기록을 조회하고, 공동 저장은 서로 다른 활성 일반회원 **5계정 이상**인 조합만 표시한다. 저장을 주문이나 구매 확정으로 세지 않는다.

## 챗봇: 공개 근거 검색 + 권한 있는 현재 기록 조회

RAG는 승인한 공개 가이드·비교 자료·검토된 분석 요약에서 근거를 찾고, 기존 서버의 **Qwen3-1.7B** 모델로 관련 근거를 선택해 답변을 구성하는 방식이다. 화면에는 “모델이 선택한 근거 안내”와 출처 카드·관련 링크·확인 시각을 제공한다. 현재 공구·커뮤니티·본인 저장·설정은 서버가 허용된 읽기 도구로 조회하고, 응답 직전 권한·revision·공개 상태를 다시 확인한다. 본인 기록은 서버에서 조합하며 생성 모델이나 분석 시스템에 보내지 않는다.

모델이 회원 ID·SQL·임의 URL·쓰기 작업을 선택하지 않는다. 근거가 없으면 부족함을 알리고, 확인되지 않은 가격·할인·재고·인증이나 의료 판단을 만들지 않는다. 추론·검색·검증 실패는 실패 상태로 표시한다.

**Opik은 답변 원문을 수집하는 기능이 아니다.** 고정 평가에서는 실제 추적 52개 저장을 조회했다. 요청 관측에는 공개 출처 ID·revision, 단계 상태·시간, 도구 종류·횟수, 고정 오류 코드만 허용하며 질문·답변·이메일·닉네임·회원/대화/요청 ID를 보내지 않는다. SDK의 input/output/thread_id는 null이다.

고정 평가 snapshot08은 기존 40문항과 검토된 추가 12문항의 **반복 회귀 52/52**, 모델 답변의 에이전트 내용 검토 **36/36**, 원래 정답 기준 **Recall@5 0.944444**다. Recall@5는 적용 가능한 질문에서 상위 5개 검색 근거가 정답 근거를 얼마나 찾았는지 보는 지표다. 새 독립 표본의 답변 정확도나 사람 평가가 아니며, 이전 실패와 중간 결과도 보존한다.

## 실제 이용 반응은 동의한 계정으로 측정한다

최근 30일의 위치·플랫폼별 **CTR = 고유 클릭 계정 수 ÷ 고유 노출 계정 수**다. 노출은 화면의 50% 이상이 1초 연속 보였다는 클라이언트 보고를 기준으로 하며, 계정·항목·위치·플랫폼·한국 날짜로 중복을 관리한다. 기본은 미동의이고 비회원·운영자·비동의 회원은 통계에서 제외한다. **1~4명인 분자·분모와 관련 비율은 숨긴다.** 5명 기준은 소수 집계를 줄이는 운영 정책이며 익명성이나 통계적 유의성을 보장하지 않는다.

서버가 확인한 신규 저장·관심만 30분 이내 마지막 측정 클릭에 연결한다. 95% Wilson 구간과 표본 기준을 사용하며, 최소 200개 노출 계정과 클릭·미클릭 각 20개 계정 전에는 효과 판단을 보류한다. 이 기준을 넘더라도 관찰 결과다. **CTR·구매·매출 개선 수치는 아직 입증하지 않았다.** 합성 계정의 시연 수치를 운영 성과로 발표하지 않는다.

## 짧은 시연 동선

합성 계정과 검증 환경에서 다음 순서로 기능을 보여준다. 운영 공개 배포 상태는 아래 출시 기록을 기준으로 설명한다.

1. 비회원으로 공구 목록 → 상세의 출처·확인 시각·외부 판매처 안내 → 배송비 포함 단가 비교.
2. 로그인 후 수요 글·공구 연결·저장 → 웹/앱의 같은 계정에서 다시 조회해 공유 기록 확인.
3. 챗봇에 비교 기준 질문 → 출처 카드·확인 시각 확인 → 본인 저장 조회와 근거 부족 답변 비교.
4. 신고 → 운영자 사유 입력·숨김 → 공개 상세와 연결 수요의 노출 변화 확인. 분석 화면은 실제 집계 조건을 충족한 값만 표시.

## 설명의 근거

최신 47개 요구사항은 상세21개·개요26개로 구분했다. API·실제 PostgreSQL·프런트 회귀, 실제 로컬 UI, 서명 Android 산출물 검증은 각각 범위를 기록하며 전체 수용 완료율이나 실기기 성공으로 바꾸지 않는다. 변동하는 배포·공개 모델·추적 연결 상태는 [최신 출시 기록](../../build/release-20261106/COMMUNITY-ASSISTANT.md)에서 확인한다.
