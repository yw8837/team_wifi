# 회원 권한·이용정지와 OCI 캐시 승격 보안 검토

2026-11-06, 읽기 전용 검토. 실제 회원·운영 DB나 원격 서버에는 접속하지 않았다. 검토자가 만든 폐기 가능한 localhost PostgreSQL과 합성 계정만 사용했다. 검토 중 대상 소스 해시는 변하지 않았으며 검증용 PostgreSQL 55447은 종료했다.

## 범위와 방법

검토 대상은 `backend/app/admin_members.py`, 관련 테스트, `security.py`/`db.py`의 인증·트랜잭션 계약, `scripts/opik/oci.py`의 v2→v3 승격이었다. 회원 API는 실제 FastAPI ASGI와 배포 모드 요청 보호 장치, PostgreSQL SERIALIZABLE 트랜잭션으로 실행했다. 인증·권한 함수를 대체하지 않고, 읽기 직후의 동시 실행 순서만 barrier/event로 조절했다.

| 확인한 상황 | 실제 결과 |
|---|---|
| 하나의 social 재인증을 서로 다른 대상 변경에 동시에 사용 | 200/409 각 한 건. 변경 이력 한 건만 저장되고 증명 토큰은 삭제됨 |
| 두 운영자가 상대방을 동시에 일반 회원으로 강등 | 200/409 각 한 건. 합성 운영자 한 명 유지 |
| 인증과 비밀번호 확인 뒤 지연한 요청을 다른 운영자가 강등 완료한 후 재개 | 지연 요청 409. 대상 회원은 변경되지 않았고 강등된 요청자의 세션은 폐기됨 |
| 회원 정지 후 기존 인증 자료 확인 | 기존 세션 401. session/social_reauth 폐기, recovery만 유지 |
| OCI 하위 레이어 파일 → 상위 레이어 whiteout 후 같은 경로 디렉터리, 기존 v2 캐시 승격 | 빈 staging에서 v3 재구성 성공. 기존 v2 결과와 별도 표식은 previous 디렉터리에 보존됨 |
| staging 완성 후 최종 rename을 강제로 실패시킴 | 기존 root와 v2 검증 표식이 원래 경로로 복구됨 |

이 재현 범위에서는 수정이 필요한 결함을 찾지 못했다. 명시적 행 잠금이 없다는 사실만으로 재인증 재사용이나 마지막 운영자 손실을 주장하지 않았다. 실제 배포 격리 수준과 직렬화 충돌 처리를 함께 검증한 결과다. 이는 회원 제어 API의 검증이며, 모든 계정 탈퇴·관리자 복구 경로에 대한 일반적인 가용성 보증은 아니다.

## 증거와 한계

- 안전한 결과·대상 소스 해시: `artifacts/community-completion-20261106/member-security-audit.json`
- 로컬 재현 스크립트: `.runtime/member-security-audit/audit.py`
- 실제 환경: Windows, localhost PostgreSQL, 실제 ASGI 및 요청 보호 장치. 클라우드 배포나 Linux 실행 결과를 의미하지 않는다.
- SQLite 기반 기존 회원 테스트는 도메인 요청 한도를 모의한다. 이 검토의 동시성 결론은 위 실제 PostgreSQL 결과에 근거한다.
- 임시 DB 초기화 사이에 백그라운드 정리 작업이 테이블 부재를 감지한 고정 코드 경고가 있었다. 소스의 권한 검증이나 결과 상태는 대체하지 않았다.
- 이후 수정한 소스에 이 결과를 자동 적용하지 않는다. JSON에 기록한 소스 해시가 검토 대상을 식별한다.
